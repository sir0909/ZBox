## 已知限制

- 热点扫描只做 TCP 15740 端口探测，发现结果不代表已通过 PTP 握手。
- 15 秒空闲监测只在应用运行时工作；iOS 后台挂起时不保证定期执行。读取过程中不会并行发心跳。`0x200F` 可能为空槽也可能为权限问题，不自动视为已确认空槽。
- Bonjour 是否可发现 Z 30、热点扫描、会话绑定、iPhone 真机连接及各项响应均未验证；发现候选不代表已经识别为 Nikon 相机。
- CI 编译仍有 iPad 全方向/全屏相关警告；后续需在真机上决定界面方向与多任务支持。App 层必须以对应提交的 macOS 云端构建结果为准。

> **边界原则**：本目录内的代码严格独立于外层 `ZBox/source/project-files/Zbox-1.0.0-test` 安卓工程；任何 iOS 改动均只在本目录（`ios/source`）内进行；iOS 文档、日志与发布产物位于 `ZBox/IOS/`。

## M2 录像、触点对焦与预览辅助（实验功能）

- 录像采用保守安全门禁：只在取景中、机身宣告开始与停止操作且 D1F0/D1A6 均读到录像模式、D0A4 禁止原因读到零、DeviceReady 成功时，人工确认后发一次 0x920A。不会自动切换机身模式或重试。开始前持久化相机 GUID 风险标记；断线、超时、后台或重启都不能推定停止。暂停手机取帧时不自动发送停止录像或 EndLiveView；仅允许相同 GUID 机身上用户确认后发一次 0x920B。相机接受停止也需用户在原机身确认，才可清除风险标记。录像文件未自动核验；机身功能、属性格式和断电持久性未经过 Z 30 实测。
- 触点对焦只允许机身通告 0x9205 和 0x90C1、单点 AF 模式和未放大的可信取景坐标；黑边不响应。先单次移动对焦区，读新帧确认位置后才单次触发 AF，失败不重试；不自动更改 AF 模式。确认区域或 AF 命令接受都不证明光学合焦。
- 手机端九宫格、16:9/1:1/4:5 框、斑马纹、峰值边缘、预览亮度直方图可开关；分析最长边 320 像素、最多约每 0.4 秒一帧，非 RAW 曝光/合焦证据，也不修改原照片。横屏取景使用左右控制轨道，方向请求仍由系统决定。M2 页面适配不代表 Android AI/预设库 M3 功能已实现。
- **尚需真机验收**：iPhone、Z 30、录像状态与中断、触点元数据、触摸坐标、性能及所有布局。模拟器假相机通过不等于实机可用。

- iPhone 主界面默认请求竖屏，全屏时请求横屏（系统 / iPad 多任务可覆盖）；新增暖灰浅色主题、底部监看/相册导航和身份不匹配内联引导。AI 调色、预设库和姿势仍属后续 M3，导航明确标为未实现，不伪装为已完成。M2 视觉布局和系统旋转仍需真机核对，不能声称全页面与 Android 100% 一致。
- 增加连接握手期间失活后旧结果不发布和录像准备中后台取消的假相机模拟器测试。已发出的网络握手不能保证在 iOS 挂起前立即终止，但旧握手完成后会关闭，不发布为活跃连接。

## M3 预设目录与 AI 曲线生成（实验，结果以对应 CI 为准）

- 从 Android `BuiltInPresets.kt` 移植 200 套目录数据和十种分类、名称、描述、原控制点及基础参数元数据；支持搜索、分类和载入曲线。**目前只应用曲线**，基础参数、相机配置和黑白类型均不应用，因此不是完整的机身效果或安卓效果。NCP 数据的来源与 Android 原项目标注保持一致。
- 使用可配置 HTTPS OpenAI 兼容视觉服务分析用户选择的参考图。API Key 以完整 Base URL 为作用域存钥匙串，默认不跨设备同步；只有用户逐次明确确认后才发送去除元数据的最多 768 像素 JPEG 缩略图和提示词，可能产生费用，服务商会处理图片。禁止 HTTP 重定向以避免转发 Key 和图片。不保存远端返回原文，结果上限 256KiB，严格校验最多八个单调曲线点和名称，仅产生全局近似曲线、不写相机。无实机、服务商联调或隐私合规验收；任何视觉模型不能准确还原参考图成像。
- 相机写入仍未开放；完整基础参数及 AI 模型/供应商互通仍需开发测试。CI 和模拟器通过不等同设备或联网实测。

## M3 槽位写入安全原型（未连接真实 PTP 或 UI）

- `SlotWriteCoordinator` 是隔离的测试原型：先精确读取已有 614B 槽位、用机身原记录保留未知字节并生成修改副本、校验持久备份、显示目标确认信息；确认后重新读取原始槽位对比，先保存未决风险，再要求仅发送一次、精确读回一致后才清除风险。失败或不一致不自动重试，风险保留；空槽拒绝。
- `SlotBackupStore` 是本地备份/风险记录原型，独占创建、SHA-256 检查和写入后重读、文件保护及 fsync；异常/损坏风险文件保留并阻止后续操作。受 iOS 文件系统、断电与存储行为限制，不承诺掉电强持久性。备份未接入导出、恢复界面和真实相机。
- 新增包内部、仅用于假相机测试的 0x90CD 单次数据输出原型；它未接入 App 或真实相机，ACK 不代表写入成功。该原型尚无可用的应用写入入口；必须先完成会话锁内生命周期/设备 GUID 二次校验及槽位内容最后一次读取比对、并发/崩溃恢复、持久风险恢复与备份导出 UI、完整 PTP 假相机测试，方可考虑开放，且必须先做明确授权的真机验收。PTP GUID 不能视为认证。

## M3 槽位备份与假相机串联（实验增量）

- 设置页新增“槽位备份和导出（只读）”：用户手动选择 C-1…C-9，停取景并等待其他操作结束后，严格读取 614 字节已占用槽位，保存到 App 私有目录并重读校验；可以查看最近最多 200 条有效记录、显示原始数据 SHA-256 并导出原始 614B 文件。无损文件需自行安全保管，当前没有自动恢复功能。访问拒绝、空槽和其他长度均不当作有效备份；存储损坏的记录保留但不能导出。暂不承诺跨设备保存或掉电强持久性。
- 备份与连接操作互斥；若在槽位读取返回之前进入后台或断线，即使马上重新进入前台，旧读取结果也不会开始保存；已经开始的本地备份保存可能继续，返回后应刷新检查。仅发送读取命令，不会写入/删除相机。机身 GUID 不是认证，备份重读摘要不是机身源端哈希；尚未在 iPhone 和 Z 30 验证。
- `PtpSlotWriteTransport` 将已有协调器和单次 PTP 原型连接起来，模拟假相机完整流程（备份、确认、单次发送、读回）以及 ACK 丢失、后台取消等风险，但此适配器仍是包内部原型，**没有 App 写入入口，也没有连到真实相机**；实际生命周期互斥、风险恢复界面、备份恢复流程及完整设备验证尚未完成。

- `SlotWriteRecovery` 是尚未接入 UI/真机的只读风险恢复原型：识别持久风险和原备份、同 GUID 槽位与原始/目标全字节相符、用户确认后重新读取与验证，只有两次一致才解除风险；不发送写/删除命令。未知内容、断线、损坏、取消或二次读取变化时保留风险。当前没有恢复界面且 PTP GUID 非身份认证，不能替代现场检查。

- 持久风险标记使用 lstat 区分不存在和不可访问/悬空符号链接；不确定时保持阻断，不把无法读取当作安全。已开始的本地保存可能在后台继续，不能保证 iOS 挂起前完成。

## M3 未决风险的只读核对界面（实验增量）

- 槽位备份页检测到风险记录时，允许用户连接原机身、停止取景后手动发起只读核对：验证风险与备份文件、GUID、槽位原始 614B 与备份或目标逐字节一致，展示检查结果；用户明确确认已检查原机身后，再只读一次，仍一致才清除手机上的风险标记。备份文件仍保留；该流程不能恢复或写入机身，不证明过去命令是否执行。PTP GUID 不提供认证，人工检查仍必要。
- 整个读取过程参与相机操作互斥，后台/断线/离开页面将使旧确认失效；假相机 App 测试覆盖用户确认、二次读取、变化、后台及重新进入前台。iOS 随时可能挂起，若状态不明应刷新并检查原机身；实机兼容性和掉电持久性仍未知。损坏的风险记录不会被自动清除。尚没有真实相机写入入口。

- 新增仅 Debug 编译的应用层假相机写入全链路测试：验证备份先于确认、互斥、一次传输与读回，覆盖确认前进入后台、写入期间进入后台、ACK 丢失及重新打开本地风险日志后阻断后续写入。测试入口及假相机代码不进入 Release；真实写入仍未开放。
